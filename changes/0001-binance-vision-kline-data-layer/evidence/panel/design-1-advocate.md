## Verdict
Keep `data-api.binance.vision` as the spot default, but do not close the concern as-is: the build must add an allow-listed host override and must not let the 418 guard depend on a header the mirror may not send.

## The case against
The intent's open question is "which spot host is the **default**", and it lists `api.binance.com` first, the mirror second: it presupposes two hosts and a choice. The design answers by deleting the alternative ("no option to switch", spec Flagged concerns; plan Options not taken). That betrays the question as asked: an owner whose network reaches `api.binance.com` but not the CloudFront-fronted `*.binance.vision` (a WAF 403, a CDN outage, a corporate proxy) has no recourse but a code change, and the design never states the one fact that would settle the choice, the owner's own region. The plan's reason ("refused in more regions than the mirror") is asserted, not sourced, and nothing in the repository or the intent backs it.
The refusal behaviour compounds it. `um` has no mirror, and with A10 every refused fill raises `KlineGapError`; in a refused region every `load_klines` over a range that touches the last one or two days raises and every `download` exits 1, for futures always and for spot whenever the mirror is refused too. The intent proposed "gaps with the reason", so the raise is in scope, but combined with the fixed host it turns a regional refusal into a permanent failure mode the owner cannot route around.
A quieter risk: the intent's hard constraint is "never get the owner's IP banned (418)", and the design's only guard is the 80 % pause keyed to `X-MBX-USED-WEIGHT-1M` on the last response. If the mirror does not forward that header, the pause is dead code and the constraint rests on nothing; the offline tests (stub `Fetch`, fixture headers) would pass either way, so a build that follows this design proves nothing about the host it actually calls. The 451-as-gap test likewise passes whatever host is hard-coded, since the stub maps the URL the code builds.
What I would decide instead: keep the mirror as the default; add `rest_host` (API) / `CRYPTO_BACKTESTER_SPOT_REST_HOST` (env) validated against an allow-list of exactly `data-api.binance.vision` and `api.binance.com` (security-baseline rule 2: no URL from unvalidated external text; rule 7 unaffected, both are Binance hosts the intent names); and have the weight pause treat a missing header as "unknown" and pause conservatively (or at least report it) rather than skip.
I would accept the obvious resolution if the owner states that the mirror is reachable from where backtests run and that a code change is an acceptable switch, and if the build's `http.py` tests pin the no-header case explicitly.
