## Verdict
Downgrade to a nit and keep the edit: the "owner must choose between this edit and dropping the name from `__all__`" framing is a false choice; the only residue is a one-line spec amendment the owner can make at merge.

## The case against
The finding rests on spec R14 and the Acceptance line, not on any policy or framework rule. REVIEW.md reserves Important for findings that "break behavior, leak data or breach a policy"; this edit does none. The framework's test-file rule (REVIEW.md; definition-of-done; plan-template) applies to fix-type changes, and `status.yaml` says `change_type: feature`. coding-standards rule 4 forbids skipping or weakening a test: the diff keeps `test_public_api`'s exact `set(api.__all__) ==` pin and adds the one name this change introduces (diff-build.patch, `tests/test_backtest.py` hunk at line 296); the pin is tighter after the change, not looser. REVIEW.md's compliance rule asks that a departure be recorded in plan.md in the same commit; it is ("Files that change" and Risks, "The public-API test on `main`").
The alternative the finding offers, "dropping the name from `__all__`", betrays the intent: "the strategy function joins the public API in `app/backtest/__init__.py`" (intent.md Affected users), R1 ("exported from `app/backtest/__init__.py` (`__all__`)") and the Acceptance line "`sma_cross_positions` is in `app.backtest.__all__`". A name re-exported but absent from `__all__` is not public in the project's own sense (`from app.backtest import *` would not export it, and the API pin test would say the public API is unchanged while a CLI now depends on it). Pressing the owner to choose between two owner-written lines, one of which the owner wrote under a false premise, is not a decision the owner needs: the intent's constraint was written because the author believed the new tests needed no change on main, which the pinned set made untrue; the design should have caught it (a claim about today's code: `tests/test_backtest.py` pins `__all__`), and plan.md now says so.
What I would decide instead: a nit-level compliance note; the owner accepts the one-line edit by merging and amends spec R14 and the Acceptance line to "except the `__all__` entry in `test_public_api`". The proof already covers it: `test.log` shows `193 passed` with the edited pin, and `test_strategies.py::test_public_api_exports_strategy` asserts the name and identity independently.
What would make me accept the Important framing after all: if the edit had loosened the pin (`issubset`, `in`, or a removed name), if the change were fix-type with `tests_locked: true`, or if the owner had said in the intent PR that the strategy must stay out of `__all__`; none of those holds.
